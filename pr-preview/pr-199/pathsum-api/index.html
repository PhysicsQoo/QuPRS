Python API: Advanced Path-sum

The QuPRS.pathsum subpackage exposes symbolic circuit and Boolean output-state primitives. This lower-level interface is useful for studying reduction rules and constructing Path-sums directly. It is distinct from the recommended high-level verification API.

from QuPRS.pathsum import PathSum, Register, F, support_gate_set

q = Register(2, "q")
circuit = PathSum.QuantumCircuit(q)
circuit = circuit.h(0)
circuit = circuit.cx(0, 1)
assert {"h", "cx"}.issubset(support_gate_set())

Gate methods return a PathSum object; use the returned object instead of assuming in-place mutation. Gate parameters use the actual source-level signature and numerical phase conventions described by their implementation.

PathSum

The central object stores a phase polynomial, Boolean output mapping and summation variables. The methods h, cx, rz, mcx and other supported gates are attached dynamically from Gate classes. This reference reads their committed, source-generated core.pyi signatures and docstrings through Griffe's static stub merge. It does not import QuPRS or execute gate implementations while rendering the site.

PathSum

Symbolic quantum-circuit Path-sum representation.

Stores the phase polynomial P, Boolean output-state mapping f, summation variables pathvar, and reduction statistics stats. See the Path-sum and reduction guide for the mathematical conventions, including the distinction between Boolean substitutions and phase coefficients.

SymEngine phase expression. Do not implicitly reduce coefficients modulo two when constructing this value.

 required

Boolean output-state map, with output-bit ordering defined by F.

 required

Set or frozenset of internal SymEngine summation variables.

 frozenset()
stats StatisticsManager | None

Optional :class:StatisticsManager shared across operations.

 None
Notes

Gate methods such as h, cx, rz and mcx are installed from Gate subclasses by attach_gate_methods at import time. Their source-derived signatures and docstrings are also recorded in the generated core.pyi stub so that static API documentation and type tooling can discover them without executing the package.

Dynamic gate signature sources

The public gate-method names and signatures are built from Gate subclasses' gate_name, __init__, and apply declarations. The scripts/generate_stubs.py generator produces core.pyi, and the documentation CI checks that every source Gate has a matching stub method and that Griffe can discover it without runtime inspection.

The generated signatures include single-qubit methods such as h and rz(theta, qubit, is_bra=False), controlled methods such as cx(control_qubit, target_qubit, is_bra=False), and multi-qubit methods such as mcx(*qubits, is_bra=False). Some specialized names are case-sensitive (for example CRk).

F

Boolean output-state map for a symbolic Path-sum.

F[i] identifies the Boolean expression used for output bit i. Expressions are normalized to algebraic normal form (ANF) when calling :meth:sub. Boolean substitution uses GF(2) semantics; this does not imply reducing phase-polynomial coefficients modulo two.

Boolean output-state expressions and phase-polynomial coefficients belong to different algebraic domains. A Boolean substitution uses ANF/GF(2) semantics; do not apply mod 2 to the original phase polynomial when writing reductions. Reduction statistics

StatisticsManager is exposed through PathSum.stats and the high-level result's Statistics field. Its counters are diagnostic, not proof certificates; this class is not a top-level QuPRS export.

StatisticsManager

Tracks reductions performed by the Python Path-sum implementation.

Counts include total, Elim, HH, and omega. The hit rate is (Elim + HH + omega) / total when total > 0; otherwise it is zero. This is diagnostic instrumentation, not an equivalence certificate. Instances are available through PathSum.stats and result Statistics.

Notes

The counter keys and this class's location are implementation-facing; prefer the documented result object for high-level verification.

API stability

PathSum, Register, F, and gate-discovery functions are exposed by QuPRS.pathsum.__all__. This does not automatically guarantee backwards compatibility for every internal implementation detail. For SolverAdapter and weighted-CNF implementation classes, consult Weighted model counting; those are not promoted to stable public Python APIs by this reference.
