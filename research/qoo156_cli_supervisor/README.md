# QOO-156 — Rust CLI outer process supervisor (experimental)

Base source: `dev@79e975b0b21c0c650db7a76fe6e35b926c67c2c8`.
Branch: `experiment/qoo156-cli-supervisor`. No changes to the native `rust/pathsum` library.

## Resource contract

- CLI parent process parses flags only, then spawns the same Rust executable as an internal worker. The worker performs QASM input, miter/pathsum, RR, Hybrid, WMC and rendering.
- Parent's monotonic `--timeout` starts before worker startup and QASM parsing, applies to single- and dual-circuit CLI modes and cancels the worker on timeout. Timeout reports `Timeout` in quiet mode and exits 124; worker errors cannot publish partial success stdout.
- Parent waits for an OS exit event via a blocking wait thread (no 20ms polling tail) and buffers the child's stdout and stderr in anonymous files (max 16 MiB committed stdout). On a successful worker exit, the parent publishes the complete output; otherwise error diagnostics only. Parent worker-exit and OOM are not silently mapped to EQ/NEQ.
- Linux `--max-memory-mib` is explicitly hard-cgroup-v2-only. A writable/delegated cgroup is required; otherwise abort before worker start. It sets `memory.max`, `memory.oom.group`, and uses an async-signal-safe `pre_exec` write to `cgroup.procs` BEFORE the worker executable starts (including loader/QASM allocations); on timeout attempts `cgroup.kill`. The parent retains the writable descriptor until `Command::spawn` finishes. **Positive delegated-cgroup/OOM evidence still required**: hosted Linux CI commonly denies cgroup delegation. No unsupported host is silently treated as memory-limited.
- Unix `--max-address-space-mib` sets `RLIMIT_AS` in the worker's pre-exec hook. This is a virtual-address limit, **not** an RSS/physical-memory limit; it must never be silently advertised as `memory.max`.
- Without a writable cgroup, best-effort descendant enumeration + Unix process-group kill is used to terminate the worker tree. A subprocess that re-sessions at exactly the wrong time may evade a snapshot. The Linux unit suite now explicitly exercises a detached solver-like process group; no race-free unconfined descendant guarantee yet without a cgroup/other OS containment primitive. Existing solver-specific QOO-6 child supervision remains unchanged.

## Performance admission

The Rust algorithm implementation `rust/pathsum` is intentionally identical to `dev` for this experiment. Native algorithmic CodSpeed CPU Simulation regression from this branch is **not expected**, but the new CLI is not free: process creation, context switching, spooled I/O, polling and result forwarding add fixed costs.

[First source-paired CodSpeed WallTime #41815845054](https://github.com/PhysicsQoo/QuPRS/actions/runs/41815845054) measured unchanged dev CLI (1.4–3.1ms) vs initial 20ms-polled supervisor (22.0–22.2ms) vs direct HEAD worker (1.4–3.1ms), source pinned same runner, hosted WallTime **observation only**. This confirmed the fixed 20ms polling tail, not a Rust computational regression. The event-driven supervisor was subsequently measured by [source-paired hosted CodSpeed #41817512390](https://github.com/PhysicsQoo/QuPRS/actions/runs/41817512390), adding ~1.5–2.7ms for tiny CLI cases. This is **OBSERVATIONAL_ONLY**, because CodSpeed reports a non-Macro Runner WallTime warning. True Macro Runner [#41825389124](https://github.com/PhysicsQoo/QuPRS/actions/runs/41825389124) remains QUEUED, and no incremental child-subreaper Macro result exists.

## Ganak forced-cancellation evidence correction (2026-11-04)

- [Actual pinned Ganak mode-6 experiment #41828065057](https://github.com/PhysicsQoo/QuPRS/actions/runs/41828065057) successfully observed the unmodified, **statically linked** Ganak executable (`sha256=934a79a3...`), verified `--mode=6` argv and CLI descendant ancestry, and SIGSTOP'ed the genuine solver PID on VQE4, QAOA7, Graphstate16 and QFT16. CLI returned Timeout/124 in all four cases. **However, the original claim that all four solvers leaked was wrong.** The test's `still_active()` helper incorrectly returned True on `psutil.NoSuchProcess` as well as AccessDenied, so its `live_orphan_after_cli=true` field could mark successfully removed processes as survivors.
- [Focused process-parentage run #41830778778](https://github.com/PhysicsQoo/QuPRS/actions/runs/41830778778) captured before/after snapshots of a stopped Ganak mode-6 process: immediately after CLI exit124, and again after three seconds, the original PID was **NoSuchProcess**. This directly contradicts the false orphan claim. **Treat every earlier `live_orphan_after_cli=true` value as invalid evidence, not a proven leak.** The timeout and exact real-Ganak process identities remain valid.
- [Test bug fix `eacf649`](https://github.com/PhysicsQoo/QuPRS/commit/eacf64952be78724959007454c1c783a5de29ce5) correctly classifies `NoSuchProcess` and `ZombieProcess` as terminated, and treats AccessDenied conservatively as unverified. A separate self-test now explicitly guards the missing-PID behavior before replaying Ganak. [Corrected real-Ganak run #41831505038](https://github.com/PhysicsQoo/QuPRS/actions/runs/41831505038) now **PASS**: VQE4 mode-6 PID was stopped, CLI timed out with exit124, and the PID immediately disappeared. Source-pinned original evidence archived in artifact #13323108745.
- [Experimental Linux child-subreaper hardening `fe912f3`](https://github.com/PhysicsQoo/QuPRS/commit/fe912f3be7300eac4552372089dad39fe7295e08) passed synthetic exited-worker/detached-solver CI [#41829351680](https://github.com/PhysicsQoo/QuPRS/actions/runs/41829351680), but **must not be credited as a demonstrated fix for real Ganak leaks**, because those leak observations were erroneous. The subreaper may still protect against legitimate orphan races but needs independent admission and CodSpeed overhead measurements before merge.
- [Same-runner real Ganak pre/post subreaper A/B #41832224555](https://github.com/PhysicsQoo/QuPRS/actions/runs/41832224555) **BOTH PASS**. Frozen pre-subreaper `920285eef` and hardening HEAD `a283a45` used the same pinned Ganak v2.8.0 SHA, VQE4 source file, original `rust/pathsum` tree, correct PID classifier, and one Ubuntu 24.04 runner. Real solver process `--mode=6` was SIGSTOP'ed in both variants; CLI exited `Timeout` code124; the original PID was absent immediately and again after three seconds in both. This proves subreaper is **not needed to make this normal solver timeout case work**, not that subreaper never improves unexpected-worker-exit safety. Artifact [#13324055415](https://github.com/PhysicsQoo/QuPRS/actions/runs/41832224555/artifacts/13324055415) contains exact PIDs, start times and checksums. No performance claims from the A/B wall-clock durations.

## Memory hard-limit admission status

- [Hosted delegated systemd-scope probe #41825201847](https://github.com/PhysicsQoo/QuPRS/actions/runs/41825201847) **NOT_ADMITTED**: the runner could not write an effective new delegated child `memory.max`.
- [Privileged Docker with private cgroup namespace probe #41833214523](https://github.com/PhysicsQoo/QuPRS/actions/runs/41833214523) **NOT_ADMITTED**: Ubuntu 24.04 hosted runner Docker 28.0.4 returned `Permission denied` when writing a freshly-created cgroup's `memory.max`, despite `--privileged --cgroupns=private`. Its root cgroup mount appeared rw, but write permission for memory.max was absent. The test capacity gate correctly skipped expensive Rust building, did not claim a positive OOM event, and preserved evidence.
- A real physical-memory OOM certificate requires a dedicated Linux VM/container environment with a genuinely delegated writable memory controller. Unix `RLIMIT_AS` is *not* an acceptable replacement for this evidence. macOS physical RSS cap remains unsupported.

## Child-subreaper necessity A/B (2026-11-04)

- **Normal real Ganak SIGSTOP→Timeout: both pre and post passed.** [Run #41832224555](https://github.com/PhysicsQoo/QuPRS/actions/runs/41832224555), source-paired frozen pre `920285eef` vs HEAD, identical Ganak and Rust core, test CLI exit124 and no orphan.
- **Real Ganak SIGSTOP→intentional Rust worker SIGKILL: both pre and post passed.** [Run #41833398697](https://github.com/PhysicsQoo/QuPRS/actions/runs/41833398697), [artifact #13325041206](https://github.com/PhysicsQoo/QuPRS/actions/runs/41833398697/artifacts/13325041206). Both confirmed genuine pinned mode-6 solver, worker SIGKILL, CLI WorkerFailed exit125 (no scientific EQ/NEQ), original Ganak PID gone after CLI exit. This targeted A/B **does not demonstrate an incremental benefit** from the Linux `PR_SET_CHILD_SUBREAPER` code. Prior output classifier `HEAD_HARDENING_CONFIRMED` was misleading because it only checked that HEAD passed; it did not assert that PRE failed. It has been fixed to `BOTH_PASS_NO_INCREMENTAL_BENEFIT_OBSERVED`. No need to rerun native builds solely to rename an evidence classification.
- **Scope**: the debug-only synthetic test that leaves a detached `setsid sleep` process on worker failure still demonstrates potential protection for unusual orphan topologies; this is defense-in-depth, not demonstrated to be necessary for actual pinned GPMC/Ganak tests. Do not merge this Linux-only complexity on an unsupported performance claim. CodSpeed Macro Runner comparison of final source remains queued; hosted data are observational.
- **Memory hard cap**: [privileged Docker capability probe #41833214523](https://github.com/PhysicsQoo/QuPRS/actions/runs/41833214523) could not write `memory.max` (`Permission denied`) on GitHub-hosted Ubuntu, even in `docker run --privileged --cgroupns=private`; certificate remains `NOT_ADMITTED`, not PASS. A genuinely delegated cgroup-v2 self-hosted Linux VM/runner is still needed for the positive page-commit OOM witness.
